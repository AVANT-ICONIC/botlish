# Mutants of the hash-table experiment's implementations
# (audit/hash-table/tools/mutate.tcl; HASH-TABLE-EXPERIMENT.md,
# "Correctness"): each a deliberate bug of the kind the brief names (wrong
# bucket index, collision not checked, duplicate insert, resize loses an
# entry, wraparound broken, probe terminates too early, load threshold off
# by one, equality omitted after a hash match) or of a removal routine,
# written against one implementation's text.
#
#   @@ NAME DESCRIPTION
#   ## impl/IMPL.bot
#   <<<<
#   text to replace (must occur exactly once in the file)
#   ====
#   replacement
#   >>>>
#
# Equivalent mutants are not listed; the ones the brief names that are
# equivalent in a representation are explained beside it instead:
#
#   * "equality omitted after hash match" in an implementation that stores
#     full 61-bit hashes (lp, rh, chain): two distinct keys of one key kind
#     with equal 61-bit hashes are needed to observe it, and none is known
#     for these key kinds (tools/model.py's bhash; no 61-bit FNV-1a
#     collision of decimal Int or short String keys was found or sought).
#     The hash-only comparison is therefore unobservable through the
#     interface; ht0, which stores no hashes, carries the mutant.
#   * "compare the stored hash" omitted (key equality alone) is correct by
#     construction: it only costs time.
