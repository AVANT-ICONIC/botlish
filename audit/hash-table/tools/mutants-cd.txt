# Mutants of the hash-table experiment's compact dict, impl/cd.bot
# (audit/hash-table/tools/mutate.tcl -file THIS; the format of
# tools/mutants.txt): each a deliberate bug of the kind the brief names
# (wrong bucket index, collision not checked, duplicate insert, resize
# loses an entry, wraparound broken, probe terminates too early, load
# threshold off by one, equality omitted after a hash match) or of the
# compact dict's own invariants: the index holds entry numbers, not slots
# (an entry is addressed by its number, -1 alone is empty, entry 0 is an
# entry), an appended entry's number is the entry count before the push,
# the index rebuild after growth (every entry, its own number, homed by the
# new capacity, at the first empty slot), and the insert that triggers
# growth.
#
#   @@ NAME DESCRIPTION
#   ## impl/IMPL.bot
#   <<<<
#   text to replace (must occur exactly once in the file)
#   ====
#   replacement
#   >>>>
#
# The brief's kinds that are equivalent, or do not exist, in this
# representation, and what replaces them here:
#
#   * "equality omitted after hash match" with the full stored 61-bit hash
#     is unobservable (tools/mutants.txt explains why: no two keys of one
#     kind with equal 61-bit hashes are known). Listed instead, as in
#     tools/mutants-chain.txt: a lookup that trusts a match of the hashes'
#     low 6 bits and omits the key comparison, the bug of a table that
#     stores a truncated hash -- killed by the collide profiles, whose keys
#     share their low hash bits. Omitting the stored-hash comparison
#     instead (key equality alone) is correct by construction: it only
#     costs time. Not listed.
#   * home() itself shifted by one (h + 1) is equivalent: every operation
#     (lookup, insert, rebuild) agrees on the shifted home, so the index is
#     a consistent linear-probing index over another hash. The listed
#     wrong-index mutants shift or truncate one side only.
#   * The rebuild placing the entries in another order (reversed, say) is
#     equivalent through the interface: linear probing without removal
#     leaves every key reachable from its home whatever the insertion
#     order (each key's slot is the first empty slot of its sequence when
#     it was placed, and slots only fill), so only which index slot holds
#     which number -- the probe counts -- changes, and `probes` is a
#     diagnostic the fuzzer does not check. Not listed.
#   * Growth recomputing the triggering key's hash and probe (a recursive
#     put on the grown table instead of placed) is equivalent: the key is
#     still absent and the grown table is not full. Not listed.
#   * "Resize to the same capacity" (create(slots(t), -1)) and an index
#     created without its -1 fill are not listed: the first never grows the
#     index, so it fills up and the probe for an empty slot never
#     terminates -- a hang on the backends that turn tail calls into loops,
#     not a kill (tools/mutants-rh.txt says the same of its non-terminating
#     mutants); the second fails the first lookup of an empty table.
#   * Removal does not exist (`# drop: no`: the fuzzer sends no drops), and
#     `from_lists` is not exercised by the trace driver (it is lpa's loop
#     over `put`, unchanged). Neither is mutated.
